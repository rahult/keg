Keg 0.12.0 brings gRPC and HTTP/2 to an app's name, makes what a person approves exactly what is merged, and stops the Mac losing connections to apps under load. Read "Upgrading from 0.11.1" before you upgrade: the name router is stricter, and nodes before this release refuse the new fields.

## New

- **A piece of work's agent reaches its model through Keg's gateway, with no key in its machine.** Once `keg assistant setup` is done, each round of a work gets a door to the model of its own, reached only from its machine and only while the round runs; Pi is pointed at it and given no key, and the project needs no `.env`. Every call is counted against that work's $2 a day (`keg assistant usage` shows `work:<N>`), and a work that has used its allowance stops with a sentence saying so. `keg assistant model --works` sets the model works ask.
- **gRPC, and any HTTP/2, through an app's name.** A service whose `keg.yaml` says `run.protocol: h2c` is reached with HTTP/2 at `<app>.keg.localhost`, with prior knowledge as a gRPC client dials and over HTTPS, so a Go app's gRPC no longer needs `localhost:<port>`. Keg checks every request: one connection reaches one app.
- **gRPC's own health check.** `run.health: { grpc: "" }` (or a service's full name) takes a release as ready only when `grpc.health.v1.Health/Check` says `SERVING`. A Go server answers it with `kegrpc.Health`.
- **Bring a work up to date.** A work whose base branch has moved on can no longer be approved as it is. **Bring up to date** (`keg work update <N>`) merges the base into the work, runs its checks again on the combined code, builds it again and asks again; a conflict sends it back to its agent with the files in conflict.
- **A first round's tests are counted against its base**: "e2e: 47 tests as printed, as on main: no new tests", where a first round used to have nothing to compare with.
- **A project names the image its works run in.** `work: { image: "golang@sha256:…" }` in `keg.yaml`, pinned by its digest, is the image a work's agent and checks run in; the console's and the Mac app's New work ask for one when the project names none. Keg's own machine for the work keeps Keg's image.
- **A service can be sent an app's past events.** A binding that says `from_start = true` asks, when it is installed, to be sent every event the app still keeps, from the first, then what comes after. A reinstalled query service no longer starts from nothing.
- **`keg app remove <app>`**, and Remove… on the console's Apps page. It stops the app everywhere on this node and takes back what services held for it. Its databases are kept unless `--with-data`, and `keg app remove <app> --with-data` removes them later, finding them by the app's name.
- **Security: `keg.tenant_ref`**, a reference between two tenant tables that names only the same organization's rows. A plain foreign key let one organization learn whether another's row existed.
- **Keg's own refusals, in Keg's words, in both clients.** "that email and password do not match" reaches the page as `unauthenticated`, where it used to be "refused". `keg.KegRefusal` (Go) and `kegRefusal` and `publicError` (`@keg/app`) say which.
- **The node hands out its Go client** as it does `@keg/app`: `keg app client --go`, and `/keg/app-client-go` in a piece of work.
- **Two services to read and copy.** The NATS service and the query service (DuckDB, read-only SQL) are published as examples in this repository's `extensions/`, with a guide to writing your own, [WRITE-A-SERVICE.md](../WRITE-A-SERVICE.md).
- **`keg vm disk --path <folder>`** moves the Mac's VM disk to another folder or volume while the VM is stopped, and back again. It is never put where a container may write.

## Fixed

- **On a Mac, connections to an app are no longer closed without an answer under load.** With 40 callers at once, 16% of connections were lost before; in this release none of 7,000 were. One caller's request that waited for the connection to close took 519 ms, and now takes 15 ms. Under sustained load, requests no longer slow down run after run: the node no longer reads a table of every ended connection on each request.
- **`keg start` and `keg restart` bring back a release that `keg stop` stopped**, where they refused it until it was deployed again.
- **Security: one HTTP/1.1 connection through Keg's names reaches one app.** A later request on a kept-alive connection naming another app used to reach the first. Requests that two programs could read differently are refused at the router.
- **Security: the node ends a command in a work's machine at its time limit itself**, where the limit rested on a `timeout` program inside the machine that an agent could replace. At the limit the machine is stopped, and starts again when it is next used.
- The Go client's refusals reach a Connect client's reader; a failed job is logged in a Go app; the gate says when a Go test run panicked; a page knows whether its live connection is up.

## Upgrading from 0.11.1

- `keg update`, then restart the node (`sudo systemctl restart kegd`). On a Mac the app updates itself; then Stop Keg and Start Keg, so the Linux machine runs this release's image, which the fix for lost connections needs.
- **The name router is stricter.** Through `*.keg.localhost`, a request a service and the router could read two ways is now refused: `400` for a repeated, comma-joined or `+N` Content-Length, Content-Length beside Transfer-Encoding, Transfer-Encoding on HTTP/1.0, a bare CR or LF, a folded header, a space before a colon, two Hosts, HTTP/1.1 without a Host, a target naming another host, or a malformed chunk; `501` for a coding other than `chunked`; `405` for CONNECT. A request for another app on the same connection is `421`, and over HTTPS so is a Host that is not the name connected to. `Upgrade: h2c` is taken out.
- **On a node with the assistant set up, works stop reading the project's `.env`.** Their agent asks the model a person set for works (`keg assistant model --works <model>`, the default until then), not the provider and model in the project's recipe, and each work spends from its own allowance, $2 a day: raise one with `keg assistant limits work:<N> --usd-per-day <n>`, or all with `default:work`. If the gateway (`models`) is stopped, a work's round fails and says to start it; it does not fall back to the `.env`. A work's machine needs `node` for its bridge to the gateway, which Pi needs too (the default image has it). On a node where setup was never run, nothing changes. Upgrade the `keg` command with the node: an older one cannot read the node's model settings once a model for works is set.
- **A work behind its base must be brought up to date before it can be approved**, work waiting at its gate during the upgrade included.
- **Upgrade every node before using the new fields.** A node before this release refuses a `keg.yaml` with `work:`, `run.protocol` or `run.health: { grpc: … }`, and a service whose manifest says `from_start`.
- **Each app's database is given capability file 013 at its next deploy.** It only adds `keg.tenant_ref`. Calling it builds a unique index without `CONCURRENTLY`, so writes to the parent table wait, and checks the new foreign key over the whole child table: on large tables, call it in a migration of its own at a quiet time.
- **Pages and tests that match "refused" must change.** `keg.Public`, `publicError` and `kegrpc.Status` now say Keg's own refusals in Keg's words with their own kind; for example, signing in with the wrong password is `unauthenticated` "that email and password do not match", and signing up twice is `already_exists` "that email is already signed up". `WriteError`'s answer gains `message`. An app's own refusals are still "refused".
- **HTTP/2 through the names is shared and bounded**: offered only to releases that say `run.protocol: h2c`, at most 256 connections on the node and 64 for one name. A gRPC stream over HTTPS is still cut after 60 seconds with nothing sent either way (keepalive pings keep it) and after 15 minutes in all.
