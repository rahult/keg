Architecture

One VM per container.

Docker Desktop runs all containers in a single shared Linux VM. Keg gives each container its own lightweight Apple VM via Virtualization.framework. Hardware-level isolation, not namespace tricks. 

Keg.app (SwiftUI)
  ├── Docker API Server → ~/.keg/docker.sock
  ├── Compose Orchestrator → YAML parse, topo sort, up/down
  ├── Kubernetes Bootstrap → kindest/node + kubeadm
  └── ContainerAPIClient → XPC / gRPC
        │
        ▼

Docker Compatibility

Drop-in replacement.

Your existing Docker workflow stays the same. Same CLI, same Compose files, same API. Just faster, lighter, and actually isolated.

Container Operations
# Run containers $ container run -d --name web -p 8080:80 nginx web # View logs $ container logs web 2026/04/16 - "GET / HTTP/1.1" 200 # Execute commands $ container exec web cat /etc/nginx/nginx.conf worker_processes auto; # Stop and remove $ container stop web && container rm web
Docker CLI via Socket
# Use Docker CLI with Keg $ export DOCKER_HOST=unix://$HOME/.keg/docker.sock $ docker ps CONTAINER ID IMAGE STATUS PORTS a1b2c3d4e5f6 nginx Up 2m 0.0.0.0:8080->80 $ docker images REPOSITORY TAG SIZE nginx latest 187MB alpine 3.20 7.8MB $ docker info Server: Keg (Apple Containerization) Kernel: Darwin 25.3.1
Docker Compose

Your compose files. No changes.

Bring your docker-compose.yml as-is. Keg parses YAML, resolves dependencies with topological sort, creates networks and volumes, and starts services in the right order.

docker-compose.yml
services: web: image: nginx:latest ports: - "8080:80" depends_on: - api api: image: node:20-alpine environment: - DATABASE_URL=postgres://db:5432/app depends_on: - db db: image: postgres:16-alpine volumes: - pgdata:/var/lib/postgresql/data volumes: pgdata:
Compose Lifecycle
# Start the stack $ keg compose up -d Compose up: my-app ==> Service: db ==> Service: api ==> Service: web Compose up finished. # Check status $ keg compose ps NAME SERVICE STATE my-app-db db running my-app-api api running my-app-web web running # View logs $ keg compose logs api --tail 5 # Tear down $ keg compose down
Kubernetes

Local K8s in 90 seconds.

Full Kubernetes cluster running inside an Apple Container. kubeadm init, CNI installed, control-plane taint removed, kubeconfig extracted. Ready for kubectl.

01

Create Cluster

Click "Create Cluster" in the Keg UI. A kindest/node container boots with kubeadm.

kubectl get nodes
NAME    STATUS  ROLES       AGE
keg-k8s Ready   control-plane 90s
02

Deploy Workloads

Apply your manifests. Deployments, services, configmaps, secrets. It's real K8s.

kubectl apply -f deployment.yaml
kubectl get pods
NAME         READY  STATUS
nginx-abc12  1/1    Running
03

Scale & Update

Scale replicas, rolling updates, exec into pods, tail logs. Full kubectl support.

kubectl scale deploy nginx --replicas=3
kubectl set image deploy/nginx nginx=nginx:latest
kubectl logs -f deploy/nginx
