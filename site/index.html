Docker compatibility

Drop-in replacement.
Same CLI. Same Compose. Same API.

Point DOCKER_HOST at Meadow's Unix socket and the entire Docker toolchain keeps working. No migrations, no rewrites.

container — native CLI
# Run containers $ container run -d --name web -p 8080:80 nginx web # View logs $ container logs web "GET / HTTP/1.1" 200 615 "-" "curl/8.7.1" # Exec into container $ container exec web nginx -t configuration test is successful
docker — via Meadow socket
# Point Docker at Meadow $ export DOCKER_HOST=unix://$HOME/.meadow/docker.sock $ docker ps CONTAINER ID IMAGE STATUS PORTS a1b2c3d4e5f6 nginx Up 2m 0.0.0.0:8080->80 $ docker info Server: Meadow (Apple Containerization) Kernel: per-container, Virtualization.framework

Kubernetes

Local K8s, in 90 seconds.
One click. Full kubeadm.

A real cluster — kubelet, CNI, CoreDNS, kubeconfig. Deploy, scale, exec, log. The kubectl commands you know, zero Minikube detour.

01 — Cluster up

One click. kubeadm boots.

Meadow runs kindest/node inside a dedicated Apple Container. kubeadm initializes the control plane, CNI comes up, kubeconfig drops into ~/.kube/config. No VM installer, no Homebrew dance.

$ kubectl get nodes NAME STATUS ROLES AGE VERSION meadow-k8s Ready control-plane 47s v1.31.0 $ kubectl cluster-info Kubernetes control plane is running at https://127.0.0.1:6443
02 — Deploy

Apply. Pods live.

Standard manifests. Deployments, Services, ConfigMaps, Secrets — all respected.

$ kubectl apply -f deploy.yaml deployment.apps/api created service/api created
03 — Scale & iterate

kubectl, unchanged.

Scale replicas, rolling updates, exec into pods, stream logs — identical surface.

$ kubectl scale deploy api --replicas=3 $ kubectl logs -f deploy/api
